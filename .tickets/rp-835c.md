# Fix truncated complex-table bitmap crops

Intent: fix a correctness bug found during visual evaluation: complex tables rendered as bitmaps can still be unsafe if the bitmap comes from Docling's detected TableItem crop and that crop omits right-side columns. Scope: export safer complex-table bitmap assets by using page-level rendered images and expanded/page-width crops from table provenance where available, preserve Docling's original table crop as a diagnostic sidecar, update manifests to identify the LLM bitmap source, and verify on the cropped first-document policy matrix and P174008. Non-goals: perfect table reconstruction, full visual table detector, or changing the simple-table HTML path.

## Acceptance Criteria

A table whose Docling table crop omits right-side columns is rendered in LLM Markdown/HTML using an expanded/page-width crop or page fallback that includes the full visible table width. Manifest records both original Docling crop and LLM bitmap crop/source. Tests or smoke checks cover the path selection, and P174008 plus the first-document table 15 smoke are re-run/inspected.
