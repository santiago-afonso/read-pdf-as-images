# Add generic parallel Docling batch CLI

Intent: add simple document-level CPU parallelism to the Docling PDF wrapper so users can convert multiple arbitrary PDFs with a single command, either as command-line paths or a piped/listed set of paths. Technical goal: reuse the existing per-document subprocess conversion boundary and batch manifest machinery, add a generic batch subcommand with --jobs bounded concurrency, and keep local CUDA parallelism blocked by default to avoid the Windows/WSL GPU instability previously observed.

## Acceptance Criteria

A new generic batch command accepts multiple PDF paths as arguments and from stdin/list files, writes per-document output directories and a batch manifest/CSV/JSONL, processes up to --jobs documents concurrently for CPU runs, refuses device=cuda with jobs>1 unless the existing stress override is explicit, preserves resume/skip/fail-fast/timeouts where practical, and has targeted tests plus ruff passing.
