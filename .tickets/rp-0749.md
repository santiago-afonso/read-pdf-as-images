# Implement table complexity scoring and bitmap-first exports

Intent: make Docling output safer for LLM consumption when structured table extraction is unreliable. Add deterministic complexity/extraction-risk scoring for Docling TableItem outputs and likely table-like PictureItem outputs. Use the score to decide whether the LLM-facing Markdown/HTML should include an HTML table, a referenced original table bitmap, or both with low-confidence diagnostics. Scope: implement scoring helpers, export complexity flags/score in per-table manifest records, preserve original table crops, include candidate table pictures, and keep referenced images as default. Non-goals: perfect cell reconstruction, broad refactor of unrelated PDF conversion tools, or full sample94 evaluation.

## Acceptance Criteria

Focused tests cover simple table, complex policy-matrix-like table, repeated headers, multiple year/value pairs in one cell, page-continuation flags, and picture-table candidate scoring. Wrapper smoke on P174008 pages 33-35 marks the policy matrix tables complex/bitmap_required and keeps referenced table images. Existing wrapper tests still pass.
